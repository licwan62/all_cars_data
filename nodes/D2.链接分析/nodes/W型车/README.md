# W 型车链接分析

本项目只读取上游 `D1.发货评估/output/W型车`（D1 的 W型车 聚类发布物，`--cluster-dir` 可覆盖），与皮卡项目的输入、合并测试和输出目录完全分开。下文旧名 `D1.聚类SKU/artifacts/W型车/<版本>/` 为历史批次记录，由路径兼容层解析，仅作追溯。

```powershell
python run.py
```

## 输出结构

`artifacts/<版本>/` 保留该版本的发布候选表和必要的分析与校验明细（0915.5 起为精简结构）：

- `REPORT.md`：分配口径与按尺码汇总，由 `05_输出/尺码发货汇总.csv` 生成。
- `05_输出/`：可直接发布的 `链接发货适配表.csv` 与 `尺码发货汇总.csv`。
- `02_聚类数据/`：`聚类主表.csv`（聚类档案、上架命名、发货分配、取整依据和尺寸范围）、`聚类原子明细.csv`、`关联链接明细.csv`（每对兄弟链接一行）。
- `04_校验报告/`：`聚类合并校验.csv`（含原聚类ID→新聚类ID 映射）与 `年份合并校验.csv`（只列发生合并或有冲突的聚类）。

`run.py` 的 `slim_release` 只删除可由其他列/文件推出的内容，删除前逐行核对，推不出就报错；`validate_release` 核对适配表与主表、原子明细、尺码汇总逐行一致。原始引擎导出的聚类主表会被字段解耦后的最终主表替代；旧的 `最终报告.md` 因采用旧分配口径而不再保留。

业务版（0915.6 起，`business_release.py` 生成）：SKU_NAME 按 `data/SKU修改.csv`（车型 + 适配年份或首尾年份 + 尺寸，须与每条链接一一对应）替换为业务编码，表格按用途解耦、以 SKU_NAME 关联：

- `SKU汇总表.csv`：最终汇总，一行一个 SKU。
- `1_发货量/`：`SKU发货量.csv`、`尺码发货汇总.csv`、`未发货车型.csv`。
- `2_质量检测/`：`SKU尺寸检测.csv`、`聚类合并检测.csv`、`年份合并检测.csv`、`兄弟链接分开原因.csv`。
- `3_调整记录/`：`SKU编码调整.csv`、`尺码名称调整.csv`、`年份调整.csv`。
- `4_底层明细/`：`车型适配明细.csv`。

0915.x 系列为在已有批次上的补丁：`restore_previous_shrink_current_sizes.py`（0915.2）、`add_custom_skus_to_compact_release.py`（0915.3）、`rename_to_new_size_codes.py`（0915.4，老爷车尺码改为新名 4S/4M/4L/4XL/4XXL）、`build_slim_release.py`（0915.5，精简并补齐定制 SKU 的原子明细与校验行）、`business_release.py`（0915.6，业务 SKU 编码与业务目录）。

发货数量按每个 Cluster 的预计销量占比计算；默认总供给为 801，以 3 件为最小发货单位并使用最大余数法分配，因此每笔发货量及汇总总数均为 3 的倍数。

流程依次重建 W 型车聚类候选、执行年份/尺码合并门禁，然后生成本项目的版本化 `artifacts/0914/`。

`artifacts/0914.2-make聚合/` 使用 `D1.聚类SKU/artifacts/W型车/0914.2-make聚合/` 的 `逻辑尺码 + MAKE` 聚类实验重新计算链接与发货；该版本不覆盖 public 正式发布表。
