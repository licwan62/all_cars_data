## 字段定义

| 字段 | 用途 |
|---|---|
| `dimension-id` | 外键，对应源工作簿“尺码匹配”表的 `DIMENSION-ID`；每条记录唯一。 |
| `original_size` | 源工作簿当前“自动尺码”，使用内部尺码值。 |
| `suggest_size` | 建议写入的内部尺码值。 |
| `原因` | 依次包含优先级、家族主组占比、家族总销量、建议方式、距当前边界、建议后长度余量和风险说明。 |

“家族主组占比”是同一车型家族中、当前销量最高尺码组的销量占家族总销量比例。占比越高，说明把边界项归入家族主组的聚类依据越强；但它不是版型适配结论，仍需结合余量和实物验证。

CSV 中使用内部尺码，例如 Coupe 的 `3L-0 → 3XL-0`，没有混用逻辑尺码和内部尺码。文件编码为 UTF-8 with BOM，可直接用 Excel 打开。

## 风险与应用顺序

1. 先处理 P0，再按 P1、P2 复核；同一优先级可参考家族主组占比、家族总销量和距边界距离决定顺序。
2. “手动升一档”意味着长度能够被建议尺码覆盖，但长度余量会增加，存在版型偏松风险。
3. 标记为“验证后手动降一档”的 42 条记录，其车型长度略超建议尺码现行上限，不能直接批量应用，必须先做样车或版型验证。
4. 本清单是手动调整候选集合。P1、P2 不等同于已确认变更，尤其不建议仅凭家族占比自动落库。

## 导入校验要求

应用调整前应执行以下检查：

1. `dimension-id` 必须在目标表中恰好匹配 1 条记录。
2. 目标记录当前尺码必须等于 `original_size`；不一致时停止更新并人工复核。
3. 仅把通过前两项校验且已完成业务确认的记录更新为 `suggest_size`。
4. 保留 `original_size` 作为回滚值，不要覆盖或删除。
