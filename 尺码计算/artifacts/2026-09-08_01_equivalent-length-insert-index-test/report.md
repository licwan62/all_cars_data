# 0908 等效长与插片指数尺码计算测试

本批次基于现有 `4,354` 条全量尺码结果，使用 `尺码匹配规则-0908.csv` 独立重算插片指数、等效长和自动尺码。测试包不覆盖 `public/全量数据.csv`，也不发布正式尺码规则。

## 测试目的

- 验证皮卡插片指标不再被后轮毂突出高估。
- 验证 `参考半周长` 改为仅供参考的 `等效长` 后，不改变正式长度匹配依据。
- 检查移除 `PK-WX/PK-WXXL` 分组后的皮卡匹配结果。
- 判断现有 `长上限` 能否直接用于新等效长口径。

## 计算口径

- 非皮卡插片指数：`R((前宽-MM + 后宽-MM) / 4 - 750)`。
- 皮卡插片指数：`R(前宽-MM / 2 - 750)`。
- 等效长：`R((L-MM + W-MM) × 周长系数 - 1500)`，仅作参考留痕。
- `R` 沿用 Power Query/Pandas 的五成双取整。
- 正式测试条件为 `L-MM <= 长上限` 且 `插片指数 <= 插片指数上限`。
- 尺码池的分类、CAB、版本、档位顺序、启用状态和回退逻辑保持不变。

## 结果统计

- 全量结果：4,354 条，唯一 `DIMENSION-ID` 4,354 个。
- 成功匹配：4,119 条；无可用尺码：162 条；数据不全：73 条，与原全量状态数量一致。
- 相对原自动尺码发生变化：27 条，全部为原 `PK-WX/PK-WXXL` 车型。
- 皮卡：465 条；无可用尺码 23 条；数据不全 3 条。
- 皮卡插片指数范围：-165～54；参考等效长范围：4,416～6,974 mm。
- 新结果中 `PK-WX/PK-WXXL` 为 0 条。

## 结论

皮卡插片指数公式达到预期：DRW 后轮突出不再直接推高插片需求，0908 规则下不再产生 `PK-WX/PK-WXXL` 分组。原 6 条 `PK-WX` 全部回归 `PK-L`；原 21 条 `PK-WXXL` 中 3 条回归 `PK-XXL`、18 条回归 `PK-XXXL`。

恢复使用 `L-MM` 后，全量成功、无可用和数据不全数量均回到原基线，仅 27 条目标皮卡改变尺码。等效长保留为参考列，不参与候选、余量或超限原因。本批次判定为“计算口径与目标分组验证通过”。

## 文件说明

- `input_全量数据.csv`：本轮重算基线；来自测试时的 `public/全量数据.csv` 快照。
- `input_参考尺寸计算.csv`：车形宽度系数与周长系数快照。
- `rules_尺码匹配规则-0908.csv`：本轮候选尺码规则。
- `rules_尺码匹配参数.csv`：余量容差参数。
- `reference_插片必要性.md`：本轮公式调整的理论依据。
- `pandas_analysis.py`：匹配器及公共计算函数快照。
- `run_test.py`：自包含测试入口；仅读写本目录文件。
- `result_尺码计算测试-0908.csv`：4,354 条逐车型测试结果。
- `summary_尺码计算测试-0908.json`：结果汇总。
- `validation.json`：机器验收结果与文件校验值。

## 复现方法

在本目录执行：

```powershell
python run_test.py
```

运行会覆盖本目录的 `result_尺码计算测试-0908.csv` 和 `summary_尺码计算测试-0908.json`，不会修改仓库中的正式输入或输出。

## 数据限制

当前工作区没有独立的尺寸库和销量明细源文件。本轮使用已发布全量结果中的原始毫米尺寸、分类、车形、前宽和后宽作为输入；未重新执行英寸转毫米、销量聚合、TRIM 生成和车形关联。
