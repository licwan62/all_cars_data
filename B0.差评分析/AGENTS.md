# 差评分析 Agent（B 线：差评分析表）

`id: negative-review-analysis`。没有上游流水线节点——原始差评数据是从各店铺差评/站内信
人工导出维护的台账，不是别的节点产物。做两件事：

1. **筛选**：用 `data/尺寸分析筛选规则.json` 里的关键词信号，从
   `data/差评分析汇总_皮卡信息补全.csv`（逐条差评原始记录，含皮卡车型/年份/驾驶室/货斗提取）
   里挑出"车辆主体尺寸不合适"（而非配件尺寸问题）的差评，写回 `data/尺寸分析汇总表.csv`，
   供人工核对（`src/build_size_analysis_summary.py`）。
2. **汇总发布**：人工据此把差评按 品牌+车型+结构 粒度汇总、评级，维护进
   `data/差评分析表.csv`；`src/run.py` 校验该表（键唯一、差评占比落在 0~1）通过后，原子发布为
   `output/差评分析表.csv`，供下游节点（`B1.压缩定制评分`）读取。
3. **耳位提取**：用 `data/耳位筛选规则.json` 里的关键词信号，从差评原文里识别"车罩后视镜
   开口位置"相关差评（提到 mirror/后视镜），再判断是否明确提到靠前/靠后，按 品牌+车型
   聚合、自动发布为 `output/耳位分析表.csv`（`src/build_ear_position_summary.py`），供
   `B1.压缩定制评分` 透传展示，不需要人工登记。
4. **皮卡驾驶室/货斗提取**：优先解析差评原文"车型"里的驾驶室类型（Crew Cab/King Cab/
   Double Cab/Quad Cab/Super Cab/Extended Cab/Regular Cab）和货斗长度（Long Bed/
   Short Bed，含 LB/SB 缩写），解析不到时退回结构化字段"提取驾驶室"/"提取货斗"，按
   品牌+车型 聚合、自动发布为 `output/皮卡驾驶室货斗分析表.csv`
   （`src/build_pickup_cab_bed_summary.py`），供 `B1.压缩定制评分` 拼进差评备注——同一皮卡
   车型不同驾驶室/货斗组合车身尺寸差异很大，定制时需要参考。

## 目录

- `data/差评分析汇总_皮卡信息补全.csv`：人工维护的差评原始台账（逐条评论/工单记录）。
- `data/尺寸分析筛选规则.json`：尺寸类差评的关键词信号规则，调整规则改这个文件即可。
- `data/尺寸分析汇总表.csv`：由 `src/build_size_analysis_summary.py` 从原始台账筛选生成的
  "疑似车辆主体尺寸不合适"清单，供人工核对、据此维护 `差评分析表.csv`，运行时自动重新生成。
- `data/差评分析表.csv`：人工维护的最终汇总表，键为 品牌+车型+结构；`差评占比`（0~1）优先，
  缺失时按 `严重度评级`（低/中/高）在下游打分时降级使用。
- `data/耳位筛选规则.json`：耳位（车罩后视镜开口位置）的车耳信号/靠前信号/靠后信号关键词，
  调整规则改这个文件即可。
- `data/03.耳位问题清单.csv`：由 `src/build_ear_position_summary.py` 生成的逐条耳位相关
  差评清单，供人工核对，运行时自动重新生成。
- `src/build_size_analysis_summary.py`：尺寸筛选逻辑。
- `src/build_ear_position_summary.py`：耳位提取与按 品牌+车型 聚合逻辑。
- `src/build_pickup_cab_bed_summary.py`：皮卡驾驶室/货斗提取与按 品牌+车型 聚合逻辑。
- `src/run.py`：编排入口，创建 `artifacts/<批次>/` 快照，校验通过后原子更新 `output/`。

```powershell
python src/run.py
```

## 已知限制 / 待办

- `差评分析表.csv` → 每个 品牌+车型+结构 的差评占比/严重度评级是人工判断，`src/run.py` 只做
  格式与键唯一性校验，不做筛选到汇总的自动聚合。
- 未在 `差评分析表.csv` 里出现的 品牌+车型+结构 视为"没有该维度的记录"，下游打分时不当作
  "没有差评"处理。
