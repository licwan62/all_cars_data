# 方案分析 — 归档说明

本目录集中归档"皮卡超粗车型尺码覆盖"的**方案、评价报告、复算工具与全部数据源**，供随时回溯与复算。

## 一、时间线与结论摘要

| 节点 | 内容 |
|---|---|
| 问题发现 | exception 表中 68 行"超粗"（宽体 SRW + DRW 重型皮卡）无可用尺码，占皮卡销量 13.8% |
| 根因定位 | 判定只参与**长（`长上限−L≤500`）与粗（`粗=W+2H≤粗上限`）**；当时全部 7 个皮卡档位粗上限恒为 6280，超粗车粗=6304–6589 全部超限 |
| 方案 | 新增宽体档位，粗上限放宽至 6900 |
| 落地 | 尺码表新增 **PK-WX（6000/6900）** 与 **PK-WXXL（6800/6900）**；PK-XXXL 长上限收紧 6912→6800；超粗 68 行重配（PK-WX 37 行 / PK-WXXL 45 行） |
| 结果 | **覆盖率 82.5% → 96.2%**；实体尺码 7→8；匹配层按规则（`>500 不可用 / 150–500 警戒 / 0–150 合适 / <0 过紧`）**不可用=0、过紧=0** |

## 三、方案建议值 vs 最终落地值

| 项目 | proposal 建议 | 最终落地（Excel） |
|---|---|---|
| PK-WX 长上限 | 6100 | **6000** |
| PK-WXXL 长上限 | 6950 | **6800** |
| 新档粗上限 | 6900 | 6900 |
| PK-XXXL 长上限 | 6912（未动） | **6800（收紧）** |

边界影响：PK-WXXL=6800 下最长车 Sierra 2500HD/3500HD DRW（6776.72）余量 23.3mm，属"合适（0–150）"，但贴近过紧下限；聚类 SAFETY FAIL 仅作警戒、不阻止分组（按用户确认口径）。

## 四、复算方法

在项目根目录运行（脚本内部路径基于 `pickup-cluster` 根）：

```bash
python 方案分析/05_复算脚本_evaluate_all.py
```

输出：控制台统计 + 刷新 `评价报告/匹配评价明细.csv` 与 `评价报告/集群评价明细.csv`。

## 五、注意事项

1. **`input/销量统计.csv` 与 Excel 尺码匹配不同步**（82 行自动尺码不一致、仍含 67 行旧"超粗"标记）：主流程 `main.py` 读 Excel，评价以 Excel 为准；建议择机统一导出源。
2. 规则口径（用户确认）：长度余量 `>500 不可用 / 150–500 警戒（可用）/ 0–150 合适 / <0 过紧`；聚类 SAFETY FAIL 仅告警。
3. 剩余问题（见评价报告建议清单）：真正不可用 = 34 行超余量（614 万 / 3.8%），待立项处理（跨分类复用 / 新增 PK-S 短档 / 人工清单）。
