# 压缩定制评分 Agent（A 线：压缩尺码表 + 定制需求度）

`id: compression-scoring`。承接 `A1.全量生成` 的全量表，做两件事：

1. **压缩**：按匹配尺码把逐年、逐结构的行压缩为"结构池 × 年份区间"（类似
   `pipeline_carstable_to_webapp` 项目里的 compress 步骤，核心算法在 `src/compress.py`
   独立重新实现，不依赖外部仓库路径）。
2. **评分**：结合 `data/` 里人工维护的差评分析表、人工维护进度、车耳状态登记三张表，
   为每个 品牌+车型+结构 打出"定制需求度（通用版型偏离度）"。

上游：`A1.全量生成/output/全量表_汇总.csv`。

## 目录

- `data/差评分析表.csv`、`data/人工维护进度.csv`、`data/车耳状态登记.csv`：人工维护的三张台账，
  键统一为 品牌+车型+结构。三张表当前都只有表头，需要人工陆续填入数据；没有对应记录的维度
  评分留空，不当作"不需要定制"处理。
- `data/定制评分规则.json`：三个维度的字段口径、状态映射和权重、分档阈值。先用等权重简单规则，
  调整规则改这个文件即可，不用改代码。
- `data/压缩配置.json`：压缩用的匹配尺码字段，当前固定为 `自动尺码`（全量表里覆盖率 100%；
  `发货尺码`/`OZON尺码` 覆盖率不到 30%，不适合做池化匹配键）。
- `data/结构归并映射.json`：仅用于打分键（不改写压缩表、不改写 01 的产物）的跨区域结构归并。
  美区原始数据从不标注车门数（一律记成 `SUV`），欧/俄区门数计入尾门，常规四门 SUV 在欧俄计为
  `SUV 5dr`；两者是同一种车身，打分时要算同一个 品牌+车型+结构 键，否则会在
  `定制需求度评分.csv` 里对同一台车出现两行（曾出现过 Acura MDX 的例子）。`SUV 3dr`
  （对应美区 2 门车型，欧俄没有对应的美区标注可比对）不在此列，仍按独立结构处理。
- `src/compress.py`：年份/结构池压缩算法。
- `src/scoring.py`：三表合并打分算法。
- `run.py`：编排入口，创建 `artifacts/<批次>/` 快照并校验通过后原子更新 `output/`。

```powershell
python run.py
```

## 已知限制 / 待办

- 结构池压缩不跨越数据缺失的年份合并（保守处理，避免虚报覆盖范围）。
- 同一 (区域,MAKE,MODEL,结构,年份) 若多个 TRIM 行给出不同"自动尺码"，按多数票取值，
  少数派写入批次的 `冲突报告.json`，需要人工抽查而非自动纠正。
- 三张人工维护表目前是空表（无历史数据可迁移），首次运行的 `定制需求度评分.csv`
  全部是"数据不足"，需要人工陆续录入后才有真实评分。
- 评分权重是初版等权重，后续按实际使用效果调整 `data/定制评分规则.json`。
