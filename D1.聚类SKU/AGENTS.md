# 聚类 SKU Agent

负责按车型、尺码和销量生成 SKU 聚类结果。自身合并规则放在 `data/`，当前交付物写入 `output/`，每轮聚类留存在 `artifacts/`。

上游：尺码计算和销量评估节点的 `output/`。

## 同车型物理尺码边界灰区（待验证方案，2026-10-19）

目标：避免同车型、同配置的记录仅因车长相差十几毫米、跨过尺码长度上限，就被拆到两个 `PHYSICAL_SKU`。灰区先确定统一供货尺码，再聚类；最终同一 Cluster 仍对应一个物理 SKU。

本节记录方案与后续实现约束，不表示灰区已生效，也不构成实物适配验证。正式业务参数、人工例外和批准记录必须落在本节点 `data/`，不能只修改本文件或把参数写死在代码中。首轮建议 `mode: review`，生成候选与审核依据；只有明确启用的规则才可改变供货尺码。

### 推荐判定条件

以下为皮卡首版建议，不直接推广到 W 型车或其他版型系列。

| 判定项 | 建议条件 |
|---|---|
| 车型身份 | `MAKE + MODEL + 版本 + 结构` 一致；保留 Raptor、Trail Boss 等版本差异 |
| 皮卡配置 | CAB、实际 BED 长度、SRW/DRW 一致；首版按精确配置，不仅按 CAB_GROUP/BED_GROUP 判断 |
| 年份 | 年份连续或重叠，允许跨代评估；不自动补齐源数据缺失的年份或适配组合 |
| 尺码关系 | 属于同一产品/版型系列的相邻两个长度档；不得跨系列、插片类型或受保护专用版型直接合并 |
| 边界范围 | 设较小档长上限为 B，候选组每条记录均满足 `abs(L-MM - B) <= 25 mm`，且原尺码覆盖相邻两档 |
| 整组尺寸跨度 | `max(L)-min(L) <= 50 mm`，宽、高也分别不超过 50 mm；不是只检查相邻两条的差值 |
| 统一方向 | 统一到这两个档位中的较大档；该档必须覆盖整组，不以灰区名义继续跨档升级 |
| 目标适配 | 每条记录重新校验目标尺码的分类、尺码池、插片指数上下限、白名单及其他有效限制 |
| 目标长度余量 | 建议自动通过范围为 `50 <= 目标长上限 - L-MM < 500 mm`，并同时满足 A0 当前规则；取约束交集 |
| 不满足条件 | 保持原归属，记录拒绝原因或转人工审核；尺寸、身份或规则信息缺失时不自动通过 |

`±25 mm` 是边界范围，`50 mm` 是整组尺寸跨度，目标长度余量是升码后的适配约束，三个概念必须分别配置。历史聚类配置中的 `min_length_margin_mm: 50` 是安全告警依据，不能据此宣称现行聚类已强制执行本方案。

尺码上限及有效适配规则读取 A0 当前 `output/US/尺码规则.json`；相邻关系限定在同系列内，不能把所有尺码仅按长度排序。不得沿用研究脚本里写死的旧尺码名和长度上限。建议新增 `data/灰区政策.yaml`，起始配置草案如下（尚未创建或启用）：

```yaml
schema_version: 1
mode: review
pickup:
  boundary_band_mm: 25
  max_group_spread_mm:
    length: 50
    width: 50
    height: 50
  max_missing_years: 0
  adjacent_sizes_only: true
  target_strategy: larger
  target_length_margin_mm:
    min: 50
    max_exclusive: 500
```

### 分组与执行顺序

1. 从上游当前 output 读取原始尺寸、身份、自动尺码及规则，完成配置标准化和候选识别。
2. 在同车型、同配置内，以相邻档边界建立年份连续的候选组，纳入满足条件的同档前后记录；不能只调整紧邻边界的一对记录，留下同一小尺寸族的残余拆分。
3. 每次扩组都重验整组边界范围、长宽高最大跨度、年份覆盖和目标适配。禁止用不受限的传递合并：A 接近 B、B 接近 C，不代表 A/B/C 整组通过。候选重叠或有多个分法时，首版转人工审核，不能由输入行序决定结果。
4. 审核模式只输出建议；获准执行时生成 D1 供货尺码，再按供货尺码聚类、生成原子归属映射并执行合并/标题覆盖检查。
5. 保留 A0 原始自动尺码及原始长度余量，另记目标尺码和目标长度余量；不改写上游 output，不伪造原始匹配结果。
6. 每个真实适配原子仍须唯一归属最终 Cluster 和供货尺码。跨原尺码的调整必须有已启用政策或明确例外依据，不能直接关闭物理 SKU 冲突检查。消费者标题也不得产生对其他供货 SKU 的真实原子重复覆盖。
7. 输出审核和身份迁移结果；按根目录约定创建新 RunBatch，校验通过后才更新 output。D 线按需运行、点名发布，不因本方案文档更新自动重跑或发布。

建议审核明细至少包括：`DIMENSION-ID`、原自动尺码、原长度余量、建议/最终供货尺码、目标长度余量、灰区组 ID、政策 ID、候选边界、整组长宽高跨度、调整原因、审核状态、原/新 Cluster 或 LINK_ID。规则版本、上游版本及来源按 run/manifest 追踪；销量只统计一次。

### 当前数据案例与反例

以下为 2026-10-19 分析时 A0 US 全量表（版本 `20261019_10`）的示例，不是长期生效的车型白名单；后续运行必须重新核对当前数据。

| 车型配置 | 年份 | 车长 mm | 原尺码 → 建议统一尺码 | 目标长度余量 mm |
|---|---|---|---|---|
| Cadillac Escalade EXT，Crew，5.3′ | 2002–2006 / 2007–2013 | 5624 / 5639 | PK-M、PK-L → PK-L | 276 / 261 |
| Ford F-150 Raptor，SuperCrew，5.5′ | 2017–2020 / 2021–2026 | 5890 / 5908 | PK-L、PK-XL → PK-XL | 310 / 292 |
| Ford F-250/F-350 Super Duty，SuperCab，6.8′ | 2008–2010 / 2011–2016 | 5888 / 5903 | PK-L、PK-XL → PK-XL | 312 / 297 |

Super Duty 同配置还包含 1999–2007 的 5878 mm 记录。1999–2016 三段年份连续，整组车长跨度仅 25 mm，宽高跨度也满足建议范围，应整段评估统一到 PK-XL；对应长度余量为 322 / 312 / 297 mm。F-150 Raptor 的 2011–2014 与 2017–2020 之间缺少年份，不自动填成连续覆盖。

不能仅凭车长接近升码：Chevrolet Avalanche 1500 两代车长差 10 mm、车高差 84 mm；Ram 1500 Regular 6.4′ 两代车长差 33 mm、车高差 69 mm。两者不满足首版高差阈值，应转人工审核。

### 可选策略与职责边界

- 默认建议统一升码，控制升码后的松量并验证目标版型；长度、宽度、高度相近不等于轮廓、镜袋等实物适配已验证。
- 放宽较小档长度上限需要版型或试套依据，应登记为精确车型例外；不建议全局增加小档上限或允许负余量。
- 仅扩大较大尺码链接的兼容范围属于 D2 链接政策；不得仅靠扩大标题覆盖来代替 D1 供货归属和唯一性校验，也不改变既成发货事实。
- Cluster 减少不等于库存物理尺码种类减少。需分别统计边界拆分消除数、改码记录/原子数、Cluster 数、物理尺码种类、受影响活动链接及发货映射。LINK_ID 延续、合并或退役须输出迁移关系，不能把换尺码视为无需审核的名称调整。

### 正式实施前的检查

2026-10-19 分析时，D1 在 `pipeline.json` 中尚未登记正式 run、tests 和 outputs，皮卡引擎保存在历史 `artifacts/皮卡/`；W 型车目标配置仍使用旧尺码名，按当前 A0 自动尺码直接筛选命中 0 行（代码另有 Bel Air 专用判断）。这些是当时状态，后续应先检查当前登记，避免重复迁移。

正式实施需把皮卡实现与维护规则整理到 `src/`、`data/`，使用根目录 RunBatch 约定并协调 D2 维护的 pipeline 登记；不得修改历史 artifact，或把历史 artifact 注册为正式默认输入。W 型车须另行确认新旧尺码和专用版型映射，再评估是否采用同类政策。

自动测试至少覆盖：边界与余量阈值的等号、宽高反例、跨 CAB/BED/轴型/版本拒绝、年份缺口、整组扩展及链式扩张拒绝、目标规则校验、输入顺序无关性、原始字段保留、真实原子唯一归属与链接迁移。正式规则变更同步更新 data、测试及新批次规则快照/差异说明。

研究参考：`D2.链接分析/皮卡/research/gray_zone_research.py` 及 `research/gray-zone-50mm/REPORT.md`。该历史研究为相邻记录两两比较，重放结果为 128 → 127 个 Cluster，物理尺码种类 6 → 6；它不是当前数据的正式验收结果，也未实现本节全部边界、整组和目标适配约束。
