# 压缩尺寸信息 Agent（A 线：压缩尺码表）

`id: size-compression`。承接 `A0.尺码计算` 的分区域全量表，按匹配尺码把逐年、逐结构的行压缩为
"结构池 × 年份区间"，US/EU/RU 各自独立分析（核心算法在 `src/compress.py`，独立实现，不依赖外部仓库路径）。

上游：`A0.尺码计算/output/全量表_US.csv`、`全量表_EU.csv`、`全量表_RU.csv`。

输出：每个区域一张无损表 `压缩尺码表_<区域>.csv` 和一张有损表 `压缩尺码表_<区域>_有损.csv`。

## 目录

- `data/压缩配置.json`：压缩用的匹配尺码字段，当前固定为 `自动尺码`（全量表里覆盖率 100%；
  `发货尺码`/`OZON尺码` 覆盖率不到 30%，不适合做池化匹配键）。
- `src/compress.py`：年份/结构池压缩算法。
- `run.py`：编排入口，逐区域读取 A0 全量表，创建 `artifacts/<批次>/` 快照，三个区域全部通过原子检查后才原子更新 `output/`。

```powershell
python run.py
```

## 压缩算法概要

1. 把每行的 `YEAR` 区间展开为逐年原子事实 `(区域,MAKE,MODEL,结构+CAB+BED,年份,自动尺码)`。
2. 同一变体同一年份多个候选尺码时按多数票取值，少数派写入批次 `冲突报告.json`。
3. 无损表 `output/压缩尺码表_<区域>.csv`：每个变体独立合并尺码相同的连续年份（不受同车型其他结构换代影响），
   再把区间与尺码完全相同的变体归并为结构池。不跨越缺失年份，不制造原表不存在的原子事实。
4. 有损表 `output/压缩尺码表_<区域>_有损.csv`：在无损结果上，同车型内尺码相同、年份间隔不超过
   `data/压缩配置.json` 的 `有损最大年份空洞` 的两行合并为“变体并集 × 年份并集”；合并行不得与其他行重叠，
   也不得覆盖尺码不同的真实原子。由此新增的、原表不存在的组合计入 `扩张原子数` 列。
5. 两张表都做原子检查：每条原子事实必须恰好命中一行且尺码一致，否则运行失败、不更新 `output/`。

## 已知限制 / 待办

- 有损合并为贪心的两两合并（扩张最小者优先），不保证全局最少行数。
- 同一 (区域,MAKE,MODEL,结构,年份) 若多个 TRIM 行给出不同"自动尺码"，按多数票取值，
  少数派写入批次的 `冲突报告.json`，需要人工抽查而非自动纠正。
