## 6. B2.定制分析 与 F0 的关系

- B2 没有登记在 `pipeline.json`，是 F0 前身：README 写明 2026-10-10 迁移到 F0。B2 现在跟踪 18 个文件，只有 3 个历史批次；`src/`、`tests/`、`data/` 下只剩未跟踪的 `__pycache__`。
- 引用关系：F0 早期发布批次 `2026-10-10_01/02_custom-analysis-release` 的 manifest 引用了 `B2.定制分析/artifacts/2026-10-10_02_custom-analysis/output/...`。F0 当前 output 的引用链（最早到 `2026-10-12_17`）**不再**指向 B2。
- 结论：**保留 B2 artifacts**（属于历史证据，归档工具扫描所有 `artifacts/`，B2 只有 3 个批次，会落在“最近 5 个”内而受保护）。如需继续瘦身，可在 F0 那两个早期发布批次归档之后，把 B2 整体一起归档到 NAS。三个只剩 `__pycache__` 的空目录可以删除（未跟踪，需确认）。

## 7. 回滚与恢复

- **源码**：已按阶段分别提交（见第 0 节），每个提交都可以单独 `git revert`。退出跟踪的文件可从 `6cb77999` 检出（例如 `git checkout 6cb77999 -- <路径>`）。
- **public**：`site_promote` 在新站点校验通过前保留 `.public.prev-<时间>`，任一步失败自动恢复。完整的历史版本可用 `python tools/site_batch.py restore <批次> --dest <空目录> --validate` 还原并校验 sha256。
- **归档**：两边归档工具都是先复制、逐文件校验、写索引，再删除本地；`--restore` / 从 NAS 复制回来即可恢复原路径。历史批次不会被改写。
- **A0 接口**：网站同时支持新接口和兼容模式；A0 回退到旧版本时自动走兼容模式（打印警告），并记录在批次的 `size_code_map.interface` 中。
