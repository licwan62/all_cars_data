# 压缩尺寸信息 Agent（A 线：压缩尺码表）

`id: size-compression`。承接 `A0.尺码计算` 的分产线全量表（国别全量表或 US 店铺全量表；US 表已含 TRIM），按原子事实把逐年、逐结构、逐版本的行
压缩为尺码表，按产线（`data/产线.yaml`：US、HNT、TM、TM_拆分、EU、RU）各自独立压缩。压缩引擎内置于 `src/sizechart/`（网站流水线原压缩步骤
`compress_to_size_chart` 的副本，来源与改动见 `src/sizechart/VENDORED.md`），不依赖外部仓库路径。

上游：`A0.尺码计算/output/<国别>/全量/全量表.csv`（国别线 US/EU/RU）与 `A0.尺码计算/output/US/店铺/店铺全量_<店铺>.csv`（店铺线 HNT/TM/TM_拆分，US 行 + 店铺发货尺码）。
另读 `02.代码映射/output/车型编码映射.csv`，为代号区域的产线生成 `CODE` 列。

默认输出（US、HNT、TM、TM_拆分、EU、RU 各 2 张，共 12 张）：`<产线>/压缩尺码表.csv`（非皮卡高度压缩）与
`<产线>/压缩尺码表_皮卡.csv`（皮卡高度压缩）。产线由目录表达，文件名不加“有损”后缀；无损表不属于 output 交付物。

## 目录

- `data/产线.yaml`：产线 → 区域（校验 DIMENSION-ID 后缀）；`代号区域`（当前 `[US]`）的产线在两张交付表首列加 `CODE`。新增店铺时，A0 `data/US/店铺/货架.yaml` 加店铺后 A0 自动产出 `US/店铺/店铺全量_<店铺>.csv`，再在此登记。
- `data/字段映射.yaml`：标准字段 ← 上游列名候选。`最终尺码 = 确认尺码 > 自动尺码 > 最终尺码 > 对应尺码`，
  与网站流水线 `configs/pipeline.yaml` 的 columns/defaults 保持一致。
- `data/车型组合.tsv`：允许在高度压缩中合并的同品牌车型组（如 Audi `A3|S3|RS3`），决定合并后的车型排序。
- `data/合并规则.yaml`：高度压缩的扩张约束（`最大空档年数`、`空档豁免尺码`），见下文第 3 步。
- `src/sizechart/`：压缩引擎（`process_tsv.transform_all_outputs`）与原子检查（`check_atom.build_atom_check`）。
- `src/run.py`：编排入口，逐产线压缩，创建 `artifacts/<批次>/` 快照，全部产线成功后才原子更新 `output/`。
- `data/ssh发布.yaml`、`src/publish_ssh.py`：把 `output/US` 的两张正式交付表发布到 `qnap-nas:/share/Public/PQData/pub_all_cars_data/size_compressed`；发布前后均校验 SHA-256。

```powershell
python src/run.py
python src/publish_ssh.py
```

## 压缩算法概要

1. **原子事实**：每行按 `前台车型`（`|` 分隔）、`结构`（`/` 分隔）、`CAB`（皮卡）展开，`年份区间` 展开为逐年，
   得到 `(品牌, 车型, 结构|CAB+BED, 版本, 年份) → 尺码`。单个年份（如 `1987`）与区间同等处理。
   `分类` 含“皮卡”的行进入皮卡表，其余进入非皮卡表；`最终尺码` 为空的行不参与。
2. **无损表**：同一 (品牌, 车型, 尺码, 结构, 版本) 只合并连续年份，不跨空洞。
3. **高度压缩（有损）表**：在无损结果上，同品牌同车型组（`data/车型组合.tsv`）内尺码相同的两行两两尝试合并
   （车型、版本 `Incl:`、结构/CAB、BED、年份并集），每次候选都做原子校验——合并记录命中的每条原子事实尺码必须与合并尺码
   一致，且左右两条原来覆盖的原子必须仍被合并记录覆盖（版本以 `/` 拼接，含 `/` 的版本名可能改变切分），否则 fallback 保留原行。
   - **积极合并**：同一原子被多条同尺码记录命中是冗余而非冲突，不阻止合并（例：Golf 的 GTI、GTI/R、R 两两年份重叠，
     任意两条合并后第三条仍命中同一原子；旧规则要求“恰好命中一条”，三条永远合不上）。
   - **合理扩张**：合并可覆盖源数据不存在的年份/结构/基础款（有损），但年份区间内连续无原子（同车型、同结构/CAB 范围）
     不得超过 `data/合并规则.yaml` 的 `最大空档年数`（当前 3；例：Prelude 1983-2001 与 2026 不桥接 24 年停产期），
     `空档豁免尺码`（无可用尺码）不受此限。不会让任何真实原子命中错误尺码。
   同一原子不同版本尺码不同时按版本分行保留，不做多数票。
4. **原子检查**：独立用 `check_atom` 把原子事实表对高度压缩表逐条核对（OK/MISS/MULTI/SIZE_MISMATCH；命中多条但尺码全部一致记 OK，
   MULTI 仅指命中的尺码不一致，源于上游同一原子有多个尺码），
   结果计数写入批次 `run.json` 的 `status`，非 OK 明细写入批次 `extra/原子检查问题_<产线>_<类型>.csv.gz`；作为核对报告，不阻断发布。

5. **尺码销量总和**：两张高度压缩表末列。A0 全量表每行的 `尺寸组销量` 按该行展开出的原子事实数均摊，再按原子检查的
   命中关系汇总到压缩记录（一个原子命中多条同尺码记录时均分），取整。销量原子键必须与压缩原子事实表完全一致，否则运行失败。
   未被任何同尺码记录覆盖的原子（原子检查 MISS）的销量无法归属，计入 `run.json` 的 `status.lines.<产线>.尺码销量总和.未命中同尺码记录`。

## 批次内容

`artifacts/<日期>_NN_compress-by-line/`（`lib/artifact_batch.py` 创建，每份字节只存一次）：
- `run.json`：上游输入引用（A0 全量表、02 车型编码映射的节点/版本/artifact_file/sha256，不复制）、`data/` 规则快照
  （sha256 + git commit；只有未提交的规则文件复制到 `rules/`）、输出 sha256、各产线状态（原 `status.json`）。
- `output/<产线>/压缩尺码表[_皮卡]-<版本>.csv`：交付物，发布时 manifest 直接引用这里，不再复制。
- `extra/*.csv.gz`：`压缩log_<产线>`（成功合并记录；fallback 按原因计数在 `run.json`）、`原子事实表_<产线>`、`原子检查问题_<产线>_<类型>`。
