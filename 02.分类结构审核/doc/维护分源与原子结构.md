# 维护分源与原子结构

## 已采用的模型

- `source` 目录继续完全由人工维护；本流程只读输入，不生成、不覆盖该目录中的任何文件。
- 普通车与老爷车可以分为两个同表头 CSV 维护，数据含义与 16 字段规范保持一致。
- 规范合并结果写入 `分类结构审核/artifacts/maintenance_union/`；主表不新增“普通/老爷”字段，来源写入独立 provenance 旁表。
- 不登记代际分区表。代际仍是记录属性，只在具体车型复核时校验。

## 原子结构约束

一行只允许一种 `结构`。`Coupe/Convertible`、`Convertible/Targa` 等带 `/` 的压缩结构不得进入新维护输入。

不能把压缩行的最大长宽高直接复制给多个结构。正确顺序是：

1. 若相应原子记录已经存在，删除复合重复行。
2. 若某结构在该年份不存在，删除错误复合行，不创建虚构记录。
3. 只有确认两种结构均存在且各自尺寸可靠时，才分别新增原子记录。

## 合并命令

```powershell
python 分类结构审核/code/build_maintenance_union.py `
  --normal <人工维护的普通车.csv> `
  --classic <人工维护的老爷车.csv>
```

工具会拒绝以下情况：表头不一致、复合结构、空或重复 `DIMENSION-ID`、同身份记录在普通车与老爷车文件中年份重叠，以及任何指向 `source` 的输出路径。合并采用普通车文件行在前、老爷车文件行在后的稳定追加顺序；冲突不会按文件顺序覆盖。

输出包括规范合并 CSV、来源旁表和 JSON 校验报告。
